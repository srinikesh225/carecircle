# Security

CareCircle holds health-related information about older adults, so access control is enforced on the server, never only in the browser.

## Reporting a problem

Please open a [GitHub issue](https://github.com/srinikesh225/carecircle/issues) titled "Security" **without** exploit details or any personal or health data, and a maintainer will arrange a private channel. This is a hackathon prototype with no bug bounty.

## How access is enforced

| Layer        | Control                                                                                                                                                                                                                                                                                                                                                         | Proof                                                                                                    |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Identity     | Firebase Authentication (email + password).                                                                                                                                                                                                                                                                                                                     |                                                                                                          |
| Data access  | [`firestore.rules`](firestore.rules): only members of a circle can read it. Joining requires the circle's passcode, compared inside the rules against a document non-members cannot read. Caregivers cannot change the medication plan or passcode. Nobody can change their own role, record a dose in someone else's name, or edit, delete or back-date notes. | 15 emulator tests in [`tests/firestore-rules.emulator.ts`](tests/firestore-rules.emulator.ts), run in CI |
| Server API   | [`api/`](api) verifies the Firebase ID token against Google's public keys, then reads circle membership **as the caller**, so the same rules apply. Email recipients come from the database, never from the request. Per-user rate limits on both endpoints. Message HTML is escaped.                                                                           | [`api/api.test.ts`](api/api.test.ts)                                                                     |
| Secrets      | `GEMINI_API_KEY` and `RESEND_API_KEY` exist only as server-side Vercel environment variables. The AI key is sent in a header, never in a URL. Nothing secret is prefixed `VITE_`, so nothing secret reaches the browser bundle. The Firebase web config in the client is public by design.                                                                      | test asserts the key is not in the URL                                                                   |
| AI output    | The model only receives that day's structured records. Replies that read like medical advice are discarded in favour of a brief composed from the records.                                                                                                                                                                                                      | [`api/api.test.ts`](api/api.test.ts)                                                                     |
| Browser      | Strict Content-Security-Policy, HSTS, `nosniff`, `frame-ancestors 'none'`, referrer and permissions policies ([`vercel.json`](vercel.json)). No production source maps.                                                                                                                                                                                         |                                                                                                          |
| Dependencies | `npm audit` must be clean in CI; Dependabot opens weekly updates. Two transitive packages are pinned to patched releases via `overrides` in `package.json`.                                                                                                                                                                                                     | CI                                                                                                       |

## Known limitations

- Rate limits are per serverless instance (in memory), a brake rather than a global quota.
- Passcodes are 8 characters from a 31-symbol alphabet (about 40 bits) and also require the circle code. There is no lockout after repeated wrong guesses.
- Email reminders are sent while a circle member has the app open; there is no server-side scheduler yet.
